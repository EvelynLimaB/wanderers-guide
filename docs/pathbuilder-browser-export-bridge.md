# Pathbuilder import using the official JSON export

Pathbuilder currently presents an anti-bot challenge to the server-side browser used by the experimental automatic importer. Wanderer's Guide does not attempt to evade that protection. The supported workflow asks the user to generate an export through Pathbuilder's own UI and provide its numeric export ID.

## Steps

1. Open the character in [Pathbuilder 2e](https://www.pathbuilder2e.com/beta/app.html).
2. In the character menu, choose **Export → Export JSON**. Pathbuilder creates the calculated JSON export and shows a numeric export ID.
3. In Wanderer's Guide, open **Import from Pathbuilder 2e** and enter both identifiers:
   - **Share ID or link**: identifies the shared editor state, including choices and Custom Files.
   - **Official JSON export ID**: the number generated by **Export → Export JSON**. This is a separate ID; do not reuse the share ID unless Pathbuilder itself gave you that exact number for the export.
4. Start the import. WG retrieves the shared state and the calculated JSON separately, validates their schemas, and compares character identity before building the WG character.

## Validation behavior

- If the official JSON export cannot be retrieved, the import stops. WG does not silently fall back to an import using only the share payload when an export ID was explicitly supplied.
- If name, class, level, or other available identity fields conflict between the share and calculated export, the import is rejected.
- Required selections that cannot be mapped are not guessed. Some Pathbuilder shares omit choices; those characters can still be rejected until the missing information is available.
- The calculated export is requested from Pathbuilder's official `json.php` endpoint using the supplied export ID. The share ID is never treated as an export ID automatically.
- No iframe, popup bridge, userscript, browser extension, or server-side bot challenge bypass is used by this flow.

## Deploy with Podman

The normal Compose stack no longer requires the headless browser worker. After pulling this branch, rebuild and recreate the frontend so the updated modal and Nginx configuration are deployed:

```bash
podman compose build frontend
podman compose up -d --force-recreate frontend
```

If the old worker container remains from an earlier deployment, remove only that now-unused container:

```bash
podman rm -f wanderers-guide_pathbuilder-automation_1
```

This command removes the obsolete worker container only; it does not remove database containers or volumes.

## Limits

Pathbuilder can still deny cross-origin requests or challenge requests to its JSON endpoint. If the user's normal browser cannot retrieve the generated export, the import will fail closed. The remaining option is to use an officially supported integration or obtain access to an approved export endpoint; WG does not bypass anti-bot controls.
